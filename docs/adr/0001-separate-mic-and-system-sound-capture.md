# 麦克风与系统声音分两路独立采集，整理时再混音；系统声音只用 Core Audio tap

麦克风照旧由 `AVAudioEngine` 采集，系统声音用 Core Audio process tap 单独建一个只含 tap 的 aggregate device，两路各写各的分片，整理时作为两条音轨放进同一个 composition 混成 recording.m4a。不把麦克风和 tap 放进同一个 aggregate device：在蓝牙耳机和内置麦克风加扬声器上实测，合并后没有声音播放时整个设备不运行，连麦克风也录不到；而且麦克风这一路是录音可靠性的根基，不该受 tap 的时钟和故障牵连。录屏开启时也不用 ScreenCaptureKit 采声音，免得出现两条系统声音路径，也让只录声音的人不必授予屏幕录制权限。

## Consequences

- 没有声音播放时，系统声音那一路实测两种情况都见过：完全没有回调（内置扬声器、蓝牙耳机各一次），或持续回调静音（蓝牙耳机一次）。所以不能用“几秒没数据”判定它停滞，也不能像麦克风分片那样首尾相接。
- 录音的时间线仍由麦克风分片决定。系统声音分片记墙钟起点，分片内没有回调的时段写盘时补静音，整理时按麦克风分片的边界逐段切开、各自经 `RecordingTimeline` 换算摆进录音；落在麦克风分片之间（断点、重试中）的系统声音无处可放，丢弃。
- 含系统声音的 recording.m4a 导出为单声道：下游对多声道的处理不一致（在线转写会把各声道的结果合并成一份，区分说话人先混成单声道），多声道有同一句话出现两遍的风险。
- 整理时另导出一份与 recording.m4a 等长对齐的 system.m4a，供以后区分“我”和对方。
- 两路时钟不同，长时间录音可能有漂移，尚未实测。
